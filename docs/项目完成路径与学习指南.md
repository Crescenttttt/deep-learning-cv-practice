### 阶段 1 · 需求分析（W13–14）

**目标**：把"做什么、用什么数据、走什么技术路线"彻底定下来。

- [ ] **最终敲定数据集**（从 TT100K / SHWD / Kvasir-SEG 三选一）
  - 选择依据：标注是否现成、数据量是否适中（建议几百~几千张）、应用场景是否好讲故事
  - 建议优先选**已有 YOLO 格式或易转换**的数据集，避免自己从头标注
- [ ] 明确系统的功能需求（输入→检测→输出的完整链路）
- [ ] 确定核心模型变体（建议 **YOLOv10-S** 或 **-N**，轻量、易训练）
- [ ] 撰写《需求分析报告》

### 阶段 2 · 概要设计（W15–16）

**目标**：环境跑通、代码跑通、数据准备好。

- [ ] 搭建 PyTorch + CUDA 环境（**严格按官方 README 的版本**，建议用 conda 独立环境）
- [ ] clone YOLOv10 官方仓库（https://github.com/THU-MIG/yolov10）
- [ ] 用官方预训练权重在 COCO 子集上**跑通推理**（验证环境无误）
- [ ] 下载数据集，划分 **train / val / test = 7 / 1.5 / 1.5**
- [ ] 转换为 YOLO 标注格式（图像 + 同名 `.txt` 标签）
- [ ] 撰写《概要设计文档》

### 阶段 3 · 模型调试（W17–18）

**目标**：微调出结果，做对比与消融，写文档。

- [ ] 在自定义数据集上**微调** YOLOv10-S/-N（加载官方预训练权重）
- [ ] 调参实验：学习率 lr、batch size、数据增广策略，追踪 mAP 曲线
- [ ] **横向对比**：YOLOv10 vs YOLOv8 vs RT-DETR（同数据集）
- [ ] **纵向消融**：复现/验证 NMS-free 分支、SCDown 等设计的贡献
- [ ] 整理训练日志、对比表、可视化 demo
- [ ] 撰写《数据处理设计文档》

### 阶段 4 · 总结汇报（W18）

- [ ] 汇总成果，制作总结 PPT
- [ ] 准备答辩问答

### 🟡 深度分析专项（建议指定 1 人主攻）

YOLOv10 深度分析的"题眼"，需吃透：

- **一致性双重分配（Consistent Dual Assignments）**
  - 一对多 vs 一对一分配的取舍
  - 双检测头：训练时都用、推理时丢掉一对多头 → 实现 NMS-free
  - 一致性匹配度量 `m = s·pᵅ·IoUᵝ`，及"监督鸿沟最小化"的推导思路
- **整体效率–精度设计**
  - 效率三件套：轻量分类头 / 空间-通道解耦下采样 SCDown / Rank 引导 CIB
  - 精度两件套：大核卷积 / 部分自注意力 PSA
- **关键消融表**：Table 2（三模块逐步叠加）、Table 3（双分配）、Table 6（分类 vs 回归误差）

> 📌 详细解读见对话记录中的《YOLOv10 论文解读》，可整理进 PPT 第 10–12 页。

## 五、3 人分工建议

> 课程默认 4 人/组，本组 3 人。把原"数据"和"文档/实验"两块合并为同一线（C），数据准备完成后无缝衔接到实验记录与写作，工作量分配也比较均衡。

| 角色 | 职责 | 对应技能 |
|------|------|---------|
| **A** 组长 / 算法主讲 | 主攻 YOLOv10 深度分析、把控进度、答辩主讲 | 深度分析专项 |
| **B** 工程 / 训练 | 环境搭建、跑通官方代码、训练脚本、调参、对比/消融实验执行 | PyTorch、Linux/命令行 |
| **C** 数据 / 文档 | 数据集收集与清洗、标注格式转换、数据划分、实验记录、文档撰写、PPT 制作、可视化 | 数据处理、写作、画图 |

> 分工不是隔离——必学内容人人都要懂，专项可指定主攻；文档由全员共同完善。3 人组的关键是 **B 跑训练时 C 同步整理结果**，避免阶段 3 末期文档赶不出来。

## 六、风险点与应对

| 风险 | 严重度 | 应对措施 |
|------|--------|---------|
| 环境配置卡壳（CUDA/PyTorch 版本不匹配） | 🟡 高频 | 严格按官方版本；conda 独立环境；预留 1–2 天容错 |

| 深度分析理论部分讲不透 | 🟡 中 | 指定 1 人主攻"一致性双重分配"，其余配合 |
| 进度拖延 | 🟡 中 | 严格对齐 W11–W18 节点；每周组内同步一次 |
